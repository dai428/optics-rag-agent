一、基础概念（必背区）

这 10 题答不出来，基本就止步初面了。
Q1什么是 RAG？解决什么问题？必背
RAG = Retrieval-Augmented Generation，检索增强生成。让大模型在回答前先"查资料"，把检索到的相关片段塞进提示词，再让模型照着答。解决三大问题：①幻觉（模型编造）②知识时效（训练截止后的事不知道）③私域知识（企业内部/个人资料模型没见过）。
大模型的参数是"冻结"的，它只会"回忆"，不会"查证"。RAG 给它接了个"外挂硬盘"。
Q2RAG 和微调（Fine-tuning）怎么选？必背
RAG：外挂知识库，不动模型权重，随时更新，便宜，适合"知识型问答"。
微调：改模型参数，改变模型的"行为/风格/格式"，数据变了要重训，贵。
选择：要注入事实知识 → RAG；要改说话风格/输出格式/领域语气 → 微调。二者可结合。
RAG 改的是"它知道什么"，微调改的是"它怎么说话"。
Q3RAG 的完整流程？必背
两阶段。
· 离线建库：加载文档 → 切块 → 向量化 → 存入向量库
· 在线问答：问题向量化 → 检索 Top-K 相似片段 → 拼进 Prompt → LLM 生成
建库是"一次性的重活"，问答是"每次都要跑的轻活"。
Q4什么是 Embedding（嵌入）？必背
把文本映射成高维向量（如 512/768/1024 维）的模型，语义相近的文本向量距离近。常见：BGE、M3E、text-embedding-3、nomic-embed。
"离得近=意思像"不是数学必然，是训练出来的——模型在海量语料上学到"常一起出现的表达该靠近"。换个模型，同一句话坐标就变了。
Q5为什么用向量检索，不用关键词检索？必背
关键词检索（BM25）只匹配字面——搜"列表推导式"命不中"list comprehension"；向量检索懂语义，但对专有名词、精确短语反而容易漏。所以生产环境常用混合检索。
两者互补：一个懂"意思"，一个懂"精确词"。
Q6什么是向量数据库？有哪些？
专门存储和检索向量的数据库，支持近似最近邻（ANN）搜索。常见：Chroma、FAISS、Milvus、Qdrant、pgvector、Pinecone。选型：小项目用 Chroma/FAISS，大规模用 Milvus/Qdrant。
几百万条向量要毫秒级找到最近的 Top-K，逐个比对太慢，必须用 ANN 索引提速。
Q7余弦相似度 vs 欧氏距离？为什么常用余弦？必背
余弦算两向量夹角（只看方向，不看长度）；欧氏算直线距离（方向和长度都看）。文本向量关心"语义方向"而非"文本长短"，所以余弦更常用。
一篇长文和一句短语，只要意思一样，方向就该一致——长度差异不该影响判断。归一化后两者等价。
Q8为什么要切块（chunk）？
①检索需要粒度：不切，向量库最小单位就是"整篇"，搜什么命中的都是整篇，等于没筛
②嵌入模型有输入长度上限（如 BGE 只吃 512 字），超长会被截断
③塞进 Prompt 的 token 有限。
切块的本质是"把检索的抓手变细"，不是为了塞给模型方便。
Q9chunk_size 和 overlap 怎么定？进阶
chunk_size 通常 200–1000 字符；overlap 取它的 10–20%。起步用 500/50，用真实问题测命中率再调。
钟摆效应：块太大 → 混了多主题，向量被"平均"掉，语义不聚焦；块太小 → 只有半句话，答不全。overlap 是防止关键句正好被切在边界上。
Q10Top-K 是什么？怎么定？
检索返回最相似的 K 个片段。K 太小 → 漏信息；K 太大 → 噪音多、占上下文、成本高。通常 3–5；配合重排则先取 20 再筛到 5。
K 是"召回率"与"精确率"的权衡旋钮。

二、进阶架构（二面深挖区）

这些是让你从"会用"到"懂工程"的分水岭。
Q11什么是混合检索（Hybrid Search）？进阶
同时用稀疏检索（BM25，关键词）+ 稠密检索（向量，语义），两路结果融合排序。
单路总有盲区，混合 = 既懂语义又保住精确匹配。
Q12RRF 是什么？进阶
RRF = Reciprocal Rank Fusion，倒数排名融合。把多路检索的排名用 1/(k+rank) 打分再相加，融合成最终排序。
不同来源的"分数"不可比（一个 0.9、一个 12.3），但"排名"可比。用排名融合，免去归一化，简单又鲁棒。
Q13什么是 Rerank（重排）？进阶
粗排（向量检索）先召回一批候选，再用 Cross-Encoder 精排。它把 query 和文档一起输入模型打分，比向量点积更准，但更慢。典型：召回 20–50 → 重排取 5。
向量检索是"各算各的"（双塔，快但粗），Cross-Encoder 是"一起看"（慢但准）。分工合作。
Q14什么是查询改写（Query Rewrite）/ HyDE？
用户问题口语化、含糊，先让 LLM 改写成更适合检索的形式。HyDE：先让模型生成一个"假设答案"，用这个答案去检索（答案和文档的表述风格更接近）。
用户问法和文档写法常有"表述鸿沟"，先"翻译"一下，命中率更高。
Q15什么是父子文档（小块检索、大块返回）？
用小块做检索（精度高），命中的小块返回它所属的大块（上下文完整）。
兼顾"检索准"和"上下文全"，解决切块的两难。
Q16什么是元数据过滤？
给文档块附带元数据（来源、时间、章节、权限），检索时先按元数据过滤再做向量检索。
能把"搜得准"变成"搜得对"——比如只搜某年份、某部门的数据。
Q17什么是 Agentic RAG？进阶
把 RAG 做成 Agent：自己判断"要不要检索""检索够不够""要不要再检索一次"（多跳）。用 LangGraph 状态机编排：retrieve → grade_documents → rewrite_query → 再检索。
普通 RAG 是"一条直线"，Agentic RAG 是"带判断的循环"——检索质量差时能自我纠正。
Q18RAG 怎么评测（Eval）？进阶
检索质量：Recall@K、MRR（平均倒数排名）、Hit Rate。
生成质量：Faithfulness（忠实度，答案是否都来自资料）、Answer Relevance（相关性）、Context Precision/Recall。
工具：RAGAS、TruLens、LangSmith。
分两段评：检索错了 → 生成再强也白搭；检索对了但答歪 → 是 Prompt 或模型问题。
Q19怎么防幻觉？
①Prompt 强约束"仅据上下文，无则答不知道" ②提高检索质量（重排/混合）③返回引用来源 ④用 Faithfulness 指标评测 ⑤置信度低时转人工。
大模型的天性是"编"。"禁止编造"这句 Prompt 不是摆设，是紧箍咒。
Q20RAG 效果差，怎么排查？进阶
分两段查。
· 检索段：命中率低？→ 调 chunk / 加混合检索 / 加重排 / 改查询
· 生成段：资料对但答错？→ 改 Prompt / 换模型 / 降 temperature
先定位是"没找到资料"还是"找到了但答错"，否则容易乱调。

三、工程与参数

Q21temperature 是什么？
控制随机性。0 = 确定、可复现（适合事实问答）；1+ = 发散（适合创意）。RAG 问答建议 0–0.3。
Q22Token 是什么？
模型处理文本的最小单位，约等于"字/词片段"。中文约 1 字 ≈ 1–2 token。计费和上下文长度都按 token 算。
Q23上下文窗口不够怎么办？
①减少 K ②压缩片段（抽取关键句）③分步回答 ④换长上下文模型。
Q24为什么不全用长上下文（把资料全塞进去）？进阶
①成本高（token 贵）②有 "lost in the middle"（中间的上下文容易被模型忽略）③延迟高。
RAG 的价值就是"精准投喂"，而不是"倒一缸水"。
Q25RAG 的成本和延迟在哪？
成本：嵌入（一次性）+ LLM 调用（每次）。延迟：检索 + LLM 生成（主要部分）。优化：缓存、批处理、小模型路由、流式输出。

四、Agent 扩展（投 AI 应用岗必备）

Q26什么是 AI Agent？必背
能自主规划、调用工具、多步执行、根据结果调整的 LLM 系统。核心 = LLM + 工具 + 记忆 + 规划。
普通 LLM 是"你问我答"，Agent 是"给我目标，我自己拆步骤去干"。
Q27Function Calling / Tool Calling 是什么？必背
让 LLM 输出结构化的调用请求（函数名 + 参数），由程序执行后把结果回传。是 Agent 的"手脚"。
模型自己不能真的"做事"，它只会"说"——Tool Calling 让它能把"意图"变成"动作"。
Q28什么是 MCP？进阶
MCP = Model Context Protocol，模型上下文协议。Anthropic 提出的开放标准，统一 LLM 与外部工具/数据的连接方式，替代各家私有插件协议。
类比："AI 世界的 USB-C 接口"——一个标准插所有设备，不用每家一个转接头。
Q29ReAct 是什么？
Reasoning + Acting。让模型"边想边做"：思考 → 行动 → 观察 → 再思考，循环。是 Agent 的基础范式。
Q30什么是多智能体（Multi-Agent）？
多个 Agent 分工协作（如研究员/写手/审核者），可互相通信。框架：AutoGen、CrewAI、LangGraph。
单个 Agent 上下文有限、容易跑偏；分工后每个角色更聚焦。
Q31Agent 的记忆怎么设计？
短期（上下文窗口）、长期（向量库检索）、情景（历史对话摘要）。参考 MemGPT / Letta 的分层记忆思路。

五、送命题（面试官最爱挖的坑）

这几题答好了，面试官会觉得"这人是真懂"。用紫色标出。
Q32RAG 能完全消除幻觉吗？
不能。它降低幻觉，但检索错、模型不听指令、多跳推理仍会出错。所以必须配合评测 + 兜底机制。
Q33你的项目用了什么技术栈？为什么这么选？
（模板，替换成你的）LangChain 做编排 + 本地 BGE 嵌入（免费、数据不出域）+ 云端 DeepSeek 生成（效果好、成本低）+ 内存向量库（小数据量够用）。
关键：要能说出"为什么不用 XX"。
Q34如果检索到的片段是错的，你的系统会怎样？
如果检索把不相关片段误判为相关混进来，大模型会照着错的编。
所以"答得对"依赖两道防线：①Prompt 兜底约束 ②检索质量。想加固就得加重排 + 相似度阈值过滤。
Q35RAG 项目里，你觉得最容易出问题的是哪一步？
（开放题，展示思考深度）切块和检索。
切块决定了"信息以什么粒度存在"，切错了后面全错；检索决定"模型看到什么资料"，检索不准，Prompt 写得再好也救不回来。所以我最看重的是这两步的调优和评测。
