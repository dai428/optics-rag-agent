RAG 评测指标详解

为 张万森 整理 · 配套 D:\Desktop\rag-demo · 2026-09-27
核心心法：评测必须"分两段"。 RAG = 检索 + 生成，中间隔着"模型"这道工序。效果不好时，你得分清是 「没找到正确资料」还是「找到了却答错」——混在一起测，等于体检不分开化验，永远查不出病因。

一、检索质量指标（Retrieval）

这一层测的是"资料找得对不对"。不需要 LLM 参与，纯数学计算。

1. Recall@K（召回率）

定义：前 K 个检索结果里，覆盖了"全部相关文档"的多大比例。测的是"有没有漏"。
Recall@K = (前K个中命中的相关文档数) / (知识库里全部的相关文档数)
例子：知识库里一共有 3 个片段跟答案相关，你的 Top-5 检索抓到了其中 2 个 → Recall@5 = 2/3 ≈ 0.67。漏了 1 个。
"该抓的有没有全抓到"。这是检索的首要指标——漏了资料，后面神仙也救不回来。

2. Precision@K（精确率）

定义：前 K 个结果里，有多少个是真正相关的。测的是"纯不纯"（噪音多不多）。
Precision@K = (前K个中命中的相关数) / K
例子：Top-5 抓到 2 个相关 → Precision@5 = 2/5 = 0.4。剩下 3 个是噪音，会挤占上下文、干扰模型。
"抓来的有多少是干货"。太高噪音 → 模型容易被带偏。

3. Hit Rate（命中率）

定义：在所有测试问题里，至少命中一个相关文档的问题占比。
Hit Rate = (Top-K 至少命中 1 个相关文档的问题数) / (总问题数)
例子：问了 100 个问题，有 85 个的 Top-5 里至少有一个相关 → Hit Rate = 0.85。
最粗粒度的"能不能用"。比 Recall 宽松，适合快速摸底。

4. MRR（Mean Reciprocal Rank，平均倒数排名）

定义：第一个相关结果排在第几位，取倒数，再对所有问题求平均。测的是"对不对得靠前"。
RR = 1 / (第一个相关结果的排名) MRR = 所有问题 RR 的平均值
例子：问"什么是 LCVR"，第一个相关片段排第 3 → RR = 1/3 ≈ 0.33。
若排第 1 → RR = 1.0（满分）。多个问题平均后 = MRR。
因为 LLM 对靠前的上下文更敏感（"lost in the middle"），排第 1 和排第 5，效果差很多。

5. NDCG（Normalized Discounted Cumulative Gain · 归一化折损累计增益）

定义：同时考虑相关性等级和位置权重的排序质量指标，是目前最"讲究"的检索指标。
名字拆开看（理解的钥匙）：
· Gain 增益：相关性等级，通常 rel = 2/1/0（很相关/一般/不相关）
· Cumulative 累计：把每个位置的增益加起来
· Discounted 折损：位置越靠后越打折——第 i 位除以 log₂(i+1)
· Normalized 归一化：再除以"理想排序的 DCG"，把分数压进 0–1
DCG = Σ (2^rel_i − 1) / log₂(i + 1) IDCG = 理想排序（相关性降序）的 DCG NDCG = DCG / IDCG
折损有多狠？位置 1 权重 = 1.00，位置 5 只剩 0.39——同一个相关文档，排第 1 和排第 5，贡献差约 2.5 倍。
完整算例：一批文档的相关性等级为 [3, 2, 2, 1, 0]（这就是理想顺序）。
【排序 A = 理想顺序】3, 2, 2, 1, 0 　DCG_A = 7/1 + 3/1.585 + 3/2 + 1/2.322 + 0/2.585 = 10.82 　IDCG　= 10.82 　NDCG_A = 10.82 / 10.82 = 1.00　← 满分 【排序 B = 刚好倒过来】0, 1, 2, 2, 3 　DCG_B = 0/1 + 1/1.585 + 3/2 + 3/2.322 + 7/2.585 = 6.13 　NDCG_B = 6.13 / 10.82 = 0.57
结论：同一批文档，只是顺序反了，NDCG 就从 1.00 掉到 0.57——这正是它的价值：专门惩罚"排序不好"。
比 MRR 更全面：MRR 只看第一个相关结果，NDCG 看整个排序、还支持相关性分级。代价：需要人工标注相关性等级，成本高。面试主动提这点显专业。

二、生成质量指标（RAGAS 四大金刚）

这一层测的是"答得对不对"。需要 LLM 当"裁判"来判断，所以又叫 LLM-as-a-Judge。

1. Faithfulness（忠实度）—— 防幻觉的核心

定义：答案里的每一个论断，是否都能在检索到的上下文里找到依据。
Faithfulness = (能在上下文中找到依据的论断数) / (答案中的论断总数)
例子：答案说了 4 句话，其中 3 句能从资料里找到出处，1 句是模型自己加的 → Faithfulness = 3/4 = 0.75。那 1 句就是幻觉。
这是 RAG 的命门指标。低了说明模型在编——要么 Prompt 约束不够，要么 temperature 太高。

2. Answer Relevance（答案相关性）

定义：答案是否切题——有没有正面回答用户的问题。
反例：问"LCVR 的优势是什么"，答了一大段"LCVR 的定义和历史"，虽然都对，但没回答"优势" → 相关性低。
"答非所问"的检测器。低了一般是 Prompt 或模型能力问题。

3. Context Precision（上下文精确率）

定义：检索回来的上下文里，真正有用的信息占比 + 是否排在前面。
本质是"检索质量"在生成侧的体现。低了 → 该加重排（Rerank）或相似度阈值过滤。

4. Context Recall（上下文召回率）

定义：回答这个问题所需的信息，是否都包含在检索到的上下文里。
低了 → 是检索漏了：该查切块策略、加混合检索、调 Top-K。

三、诊断矩阵（最实用的一张表）

拿到指标后，怎么定位问题、开什么药——这张表是面试的"加分神器"。
症状病灶药方
Context Recall 低检索漏了（该抓的没抓到）调 chunk 策略 · 加混合检索（BM25）· 增大 Top-K · 查询改写
Context Precision 低噪音多（抓来一堆没用的）加 Rerank 重排 · 相似度阈值过滤 · 元数据过滤
Faithfulness 低模型在编造（幻觉）强化 Prompt 约束 · 降 temperature · 换更强模型
Answer Relevance 低答非所问改 Prompt 模板 · 明确回答格式要求
检索指标都好，答案还错问题在生成段查 Prompt / 模型 / 是否串了上下文

四、怎么落地跑起来

工具：RAGAS（最主流）、TruLens、LangSmith、DeepEval。
跑之前要准备三样东西：
① 问题集（question）：一批真实的用户问题，20–50 条起步
② 标准答案（ground truth）：理想答案，用来算正确性
③ 检索上下文（contexts）：你的系统实际召回的内容
没有数据集的评测都是耍流氓——凭"感觉好像变好了"调参，是新手最大的坑。

五、面试怎么答（话术模板）

如果面试官问："你怎么评估你的 RAG 系统？"

"我会分两段评。检索段看 Recall@K 和 MRR，确认该找的资料有没有找到、排得靠不靠前；生成段用 RAGAS 的四大指标——Faithfulness 看有没有编造、Answer Relevance 看切不切题、Context Precision/Recall 看上下文质量。

然后我会根据指标反向定位问题：如果是 Recall 低，说明检索漏了，我会去调切块或加混合检索；如果是 Faithfulness 低，说明模型在编，我会加强 Prompt 约束。

关键是不能只看一个总分——不分段，你根本不知道问题出在检索还是生成。"
追问："为什么不能只看最终答案对不对？"

"因为 RAG 是链路，最终答案对了可能是蒙对，错了也说不清是哪一环。
举个例子：知识库里明明有答案，但检索没召回到 → 模型只能瞎猜 → 你看到答案错，却以为是模型不行，去换模型，白折腾。
分段评测才能真正定位问题，指导你优化哪一环。"
