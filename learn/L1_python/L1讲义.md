## 零、为什么 L1 是你的唯一硬门槛

调研里那句话很扎心，但准确：

> 你从「改参数」到「写工程」之间，差的**不是知识，是习惯**。

具体差在四个习惯：

| 习惯 | 没有它的后果 |
|---|---|
| 类型提示（Type Hints） | 半年后看自己的代码，不知道参数该传什么 |
| 异常处理（Exception） | 一个文件读失败，整个程序崩掉 |
| 路径处理（pathlib） | 换个目录跑就报 `FileNotFoundError` |
| 日志（logging） | 出错时只能靠 print，线上没法排查 |

**这四个习惯加起来，就是 L1 的全部内容。**

## 二、正课一：类型提示

Python 是动态类型语言——不看这里，你永远不知道 `k` 是什么。

**没有类型提示的写法**（你 rag-demo 里的现状）：

```python
def get_retriever(k=3):
    return get_vectorstore().as_retriever(search_kwargs={"k": k})
```

**问题**：`k` 是整数？字符串？`None` 允许吗？只能猜。

**有类型提示的写法**：

```python
def get_retriever(k: int = 3) -> Retriever:
    """返回检索器；拿问题去库里找最像的 k 个片段。"""
    return get_vectorstore().as_retriever(search_kwargs={"k": k})
```

**变化点**：
- `k: int` —— 声明参数类型
- `-> Retriever` —— 声明返回值类型
- 编辑器现在能给你自动补全和类型检查

### 进阶：TypedDict（重点）

当你要传一个「有固定字段的字典」时，用它：

```python
from typing import TypedDict

class CorpusInfo(TypedDict):
    documents: list[str]
    chunks: int
    embed_model: str
    chroma_dir: str
```

对比你现在的写法（`knowledge_base.py:117`）：

```python
def corpus_info() -> dict:
    return {"documents": docs, "chunks": n, ...}   # dict —— 字段名靠记
```

**为什么不重要？** 因为 **L4 之后你要写 Agent**，而 LangGraph 的整个状态（State）就是靠 `TypedDict` 定义的。写 Agent 必然要和它打交道。

**记住两条**：
1. 每个函数的参数和返回值都标类型
2. 有固定字段的字典 → 用 `TypedDict` 定义成一个类

## 三、正课二：异常处理

### 你现在的代码（`knowledge_base.py:55-58`）

```python
for f in sorted(DOCS_DIR.glob(pattern)):
    try:
        docs.extend(TextLoader(str(f), encoding="utf-8").load())
    except Exception as e:  # noqa: BLE001
        print(f"[warn] 读取失败 {f.name}: {e}")
```

**这段代码是对的，而且是好习惯。** 一个文件读失败，不该让整个索引构建崩掉。

### 但要懂「为什么」

**`try/except` 的本质**：把「可能失败的操作」圈出来，给一个体面的失败方式。

没有它：869 个片段里有一个文件编码不对 → 整个程序崩 → 你也不知道是哪个文件。
有它：跳过坏文件，打印警告，继续跑完。

### 三个层次的写法

| 层次 | 写法 | 适用 |
|---|---|---|
| ❌ 差 | 不处理，让它崩 | 快速原型，但别留到"工程"里 |
| ⚠️ 中 | `except Exception as e:` 捕获全部 | 你现在的写法，**可接受** |
| ✅ 好 | 捕获**具体**异常类型 | 生产代码 |

```python
try:
    docs.extend(TextLoader(str(f), encoding="utf-8").load())
except UnicodeDecodeError as e:
    print(f"[warn] {f.name} 编码不是 utf-8: {e}")
except FileNotFoundError as e:
    print(f"[warn] {f.name} 文件消失: {e}")
```

**为什么不都写成 `Exception`？**
因为它会**吞掉你不想吞的错误**。比如你代码里写错了变量名 → `NameError` → 被 `except Exception` 吃掉 → 你看到的是「读取失败」，实际是你自己的 bug。**调试噩梦。**

**黄金原则**：`except` 要窄，不要宽。宁可多写几个 except。

### 一个必须知道的坑：`finally`

```python
f = open("x.txt")
try:
    ...  # 用 f
finally:
    f.close()   # 无论成功失败都关
```

**但 Python 有更好的写法**——`with`：

```python
with open("x.txt", encoding="utf-8") as f:
    content = f.read()
# 出这个块，文件自动关，不需要 finally
```

你的 `pathlib` 写文件也用它：`p.write_text(content, encoding="utf-8")` —— 内部自动处理了开关。

## 四、正课三：pathlib 路径处理

**这是你代码里做得最好的地方**（`knowledge_base.py:23-25`）：

```python
from pathlib import Path

_ROOT = Path(__file__).parent.parent          # 项目根目录（app/ 的上一级）
DOCS_DIR = _ROOT / "data" / "docs"            # 语料
CHROMA_DIR = _ROOT / "data" / "chroma_db"     # Chroma 持久化目录
```

**为什么这么写是对的？** 三个理由：

1. **不写死绝对路径** —— 项目搬到别的电脑、别的盘，照样能跑
2. **不依赖「当前工作目录」** —— 不管你从哪个目录执行脚本，`__file__` 始终指向这个文件自己
3. **`/` 运算符** —— 比 `os.path.join` 好读，且**跨平台**（Windows 用 `\`，Linux 用 `/`，pathlib 自动处理）

**反面教材**（绝对不要写）：

```python
DOCS_DIR = "D:/Desktop/rag-demo/data/docs"    # ❌ 换电脑就死
DOCS_DIR = "../data/docs"                     # ❌ 取决于从哪执行
DOCS_DIR = "D:\\Desktop\\rag-demo\\data\\docs"  # ❌ 反斜杠只 Windows 认
```

**⚠️ 记住一个坑**：`Path("a/b") / "c"` 用 `/`，**不是** `//`，也不是字符串拼接。

### 常用 API

| 写法 | 含义 |
|---|---|
| `Path(__file__).parent` | 当前文件所在目录 |
| `Path(__file__).parent.parent` | 上一级目录 |
| `p / "sub" / "f.txt"` | 拼路径 |
| `p.glob("**/*.md")` | 递归匹配所有 .md（`**` = 任意层级） |
| `p.rglob("*.md")` | 等价于 `p.glob("**/*.md")` |
| `p.name` | 文件名（含扩展名） |
| `p.stem` | 文件名（不含扩展名） |
| `p.parent.name` | **父目录名** ← 练习题用到了 |
| `f.stat().st_size` | 文件字节大小 |

## 五、正课四：JSON 与文件读写

**核心原则：永远显式指定 `encoding="utf-8"`。**

Windows 默认编码是 GBK，Linux 是 UTF-8。不写 encoding 的代码，**在 Windows 能跑，到服务器上就崩**——这是新手最经典的「本地能跑线上挂」。

### 读 JSON

```python
import json
from pathlib import Path

def load_json(path: Path) -> dict:
    """读 JSON 文件；文件不存在或格式错，返回空字典。"""
    if not path.exists():
        return {}
    try:
        return json.loads(path.read_text(encoding="utf-8"))
    except json.JSONDecodeError as e:
        print(f"[warn] {path.name} 不是合法 JSON: {e}")
        return {}
```

**三个工程习惯全在这 9 行里**：
- 先判断存在性（`path.exists()`）
- 用 `path.read_text(encoding="utf-8")` 而不是 `open()`
- 只捕获 `JSONDecodeError`（窄捕获）

### 写 JSON（中文可读）

```python
def save_json(data: dict, path: Path) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)   # 目录不存在就建
    path.write_text(
        json.dumps(data, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
```

- `ensure_ascii=False` —— **不加这个，中文会变成 `\u5149\u5b66` 天书**
- `indent=2` —— 缩进，人能读
- `mkdir(parents=True, exist_ok=True)` —— 自动建父目录，且已存在不报错

### `open()` vs `pathlib`

| 任务 | 推荐 |
|---|---|
| 读全文 | `path.read_text(encoding="utf-8")` |
| 写全文 | `path.write_text(s, encoding="utf-8")` |
| 读 JSON | `json.loads(path.read_text(encoding="utf-8"))` |
| 逐行读大文件 | `with open(...) as f: for line in f:` |

**小文件一律用 pathlib，一行搞定，不用管关闭。**

## 六、正课五：logging

**你现在的现状**：整个项目里 `print` 和 `logging` 混着用。L1 之后**统一用 logging**。

### 为什么不用 print

| 场景 | print | logging |
|---|---|---|
| 想看时间戳 | ❌ 没有 | ✅ 自动 |
| 想分级（调试/正常/警告/错误） | ❌ 一锅粥 | ✅ 五级 |
| 想写文件 | ❌ 自己重定向 | ✅ 一个参数 |
| 想上线时关掉调试输出 | ❌ 删代码 | ✅ 改等级 |

### 标准写法（照抄）

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    datefmt="%H:%M:%S",
)
logger = logging.getLogger(__name__)

logger.info("开始构建索引")
logger.warning("%s 读取失败，已跳过", f.name)
logger.error("向量库构建失败：%s", e)
```

### 五个等级（从低到高）

| 等级 | 用途 |
|---|---|
| `DEBUG` | 调试细节，上线关掉 |
| `INFO` | 正常流程节点（「开始构建」「完成，869 片段」） |
| `WARNING` | **能继续但不对劲**（跳过了一个坏文件、回退到默认值） |
| `ERROR` | 出错了，功能不可用 |
| `CRITICAL` | 整个程序要死了 |

**和 `except` 的配合**（这是重点）：

```python
try:
    docs.extend(TextLoader(str(f), encoding="utf-8").load())
except UnicodeDecodeError as e:
    logger.warning("%s 编码异常已跳过：%s", f.name, e)   # 继续跑
```

⚠️ **三个坑**：
1. **不要用 f-string**（`logger.info(f"...")`）—— 应该用 `logger.info("%s", x)`。原因：日志级别不够时，前者仍会先拼字符串浪费性能。
2. **`getLogger(__name__)`，不是 `getLogger("xxx")`** —— `__name__` 自动是模块名，日志里能看出是哪个文件打的。
3. **`basicConfig` 只调一次**，通常在入口（`main.py`），别在每个模块里调。
