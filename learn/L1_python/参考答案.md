## 缺陷 ①：路径写死绝对路径

**位置**：第 20 行
```python
DOCS_DIR = Path("D:/Desktop/rag-demo/data/docs")
```

**问题**：把路径写死在代码里。

**为什么错**：
- 项目换到别的盘 / 别人电脑 → 直接死
- 团队协作时，每个人的项目路径都不一样
- 打包进 Docker 后，容器里根本没有 `D:/Desktop/...` 这个路径 → **容器起不来**

**正确写法**（对照 `knowledge_base.py:23-25`）：
```python
DOCS_DIR = Path(__file__).parent.parent.parent / "data" / "docs"
```
`__file__` 是「当前这个文件自己的路径」，所以无论从哪执行、项目搬到哪，都能正确算出 `data/docs`。

**关键理解**：这不是「能不能跑」的问题——两种写法在你这台电脑上都能跑。这是「**换环境会不会死**」的问题。工程代码要在陌生环境也活下来。

## 缺陷 ②：顶层文件被漏掉

**位置**：第 25 行
```python
for pattern in ("**/*.md", "**/*.txt", "**/*.csv"):
```

**问题**：`**/*.md` 只匹配「**子目录里**的 .md」，**不匹配顶层直接放在 `data/docs/` 下的文件**。

**验证**：我实测过——
```
**/*.md  命中 12 个    （全是子目录里的）
data/docs/ 顶层的直接文件：0 个
```
现在恰好没有顶层文件，所以**看不出问题**。但只要你在 `data/docs/` 下丢一个 `readme.md`，它就永远统计不到。

**正确写法**：
```python
for pattern in ("*.md", "*.txt", "*.csv", "**/*.md", "**/*.txt", "**/*.csv"):
```
或更简洁——先判断是不是文件：
```python
for f in sorted(docs_dir.rglob("*")):
    if f.is_file() and f.suffix in (".md", ".txt", ".csv"):
        ...
```

**关键理解**：`**/` 的含义是「零层或多层子目录」。理论上零层应该包含自己这层，但 `glob` 的实现要求 `**` 后面**必须跟路径分隔符**，所以 `**/*.md` 实际是「至少一层子目录」——**这是 Python 的坑，不是你理解错了**。

⚠️ **注意**：你原来的 `knowledge_base.py` 也有这个问题（第 53 行同样写法）。这是「代码能跑但有隐患」的典型例子——**这也是我要求你在 L1 里学会「读代码找隐患」的原因**。

## 缺陷 ③：`os.path.getsize` 没有异常处理

**位置**：第 28 行
```python
stats[group]["bytes"] += os.path.getsize(f)
```

**问题**：没有 `try/except`。三种情况会让整个程序崩掉：
1. 文件被别的程序占用 / 权限不足
2. 扫描期间文件被删除（`FileNotFoundError`）
3. 符号链接指向不存在的目标

而且要命的是——**它用的是 `os.path` 而不是 `pathlib`**。既然上面已经 `from pathlib import Path` 了，就该统一用 `f.stat().st_size`：

```python
try:
    stats[group]["bytes"] += f.stat().st_size
except OSError as e:
    logger.warning("%s 读取失败已跳过：%s", f.name, e)
    continue
```

**关键理解**：
- 一个坏文件不该让整个索引构建崩掉（对照 `knowledge_base.py:55-58`，那里做对了）
- `OSError` 是**窄捕获**——只抓文件系统错误，不吞掉你自己的 `NameError` 之类的 bug
- **风格一致性**：同一个文件里不要 `os.path` 和 `pathlib` 混着用

## 额外缺陷（加分项，找到算你厉害）

**④ 没有类型提示**
```python
def scan_corpus(docs_dir):        # 什么类型？
    ...                            # 返回什么？
```
应为：
```python
def scan_corpus(docs_dir: Path) -> dict[str, dict[str, int]]:
```

**⑤ 用 print 而非 logging**
```python
print(f"{name:12s} ...")
```
应为 `logger.info(...)`。理由见讲义第六节。

**⑥ 目录不存在时静默返回空字典**
```python
scan_corpus(Path("D:/不存在的目录"))   # 返回 {}，不报错
```
实测：`glob` 对不存在的目录**返回空列表而不报错**。这意味着你打错一个字，程序不告诉你，只是安静地统计出 0 个文件。

**工程正确做法**：入口处显式校验
```python
if not DOCS_DIR.exists():
    raise FileNotFoundError(f"语料目录不存在：{DOCS_DIR}")
```

## 本次练习的真正目的

**三个缺陷全都不影响「在你这台电脑上跑出正确结果」。**

这就是工程能力的核心——**代码的价值不在于「此刻能跑」，而在于「明天还能跑、换台机器还能跑、出问题时能告诉你哪出问题了」。**

对应到讲义第一节那张表：
| 缺陷 | 属于哪类习惯 |
|---|---|
| ① 绝对路径 | 路径处理 |
| ② 顶层漏掉 | 逻辑严谨性 |
| ③ 无异常处理 | 异常处理 |
| ④ 无类型提示 | 类型提示 |
| ⑤ print | 日志 |
