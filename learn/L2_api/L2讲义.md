## 零、为什么先学这一层

你现在会用 `LangChain` 调模型，但你大概说不清**底下发生了什么**。

L2 要做的是：**把 LangChain 帮你做的那层封装，自己手写一遍。**

```
你现在的认知：  ChatOpenAI(model=...) → agent.invoke() → 拿到答案
                 ↑ 黑盒

L2 之后的认知：  requests.post(URL, headers, json) → 解析 choices[0].message.content
                 ↑ 看得见每一字节
```

**为什么不直接用官方 SDK（`openai` 包）？**
因为 `requests` 是最底层的方式，**没有魔法**。你看到的是真实的 HTTP 请求——这层理解了，之后无论换哪家模型、哪个框架，你都能自己调通。

## 二、正课一：OpenAI 兼容接口的报文结构

**行业事实**：现在几乎所有大模型服务商（AMD 云、DeepSeek、通义、智谱、本地 Ollama）都提供 **OpenAI 兼容接口**。

意思是：**只要请求格式按 OpenAI 的来，就能通用**。你换模型只需改 `model` 字段。

### 请求（你发出去的）

```json
{
  "model": "Qwen3.8-27B",
  "messages": [
    {"role": "system", "content": "你是光学助手"},
    {"role": "user",   "content": "什么是斯托克斯参量？"}
  ],
  "temperature": 0.1
}
```

**三个 `role` 的含义**：

| role | 含义 | 用在哪 |
|---|---|---|
| `system` | 系统提示词。设定角色、规则、边界 | 放最前面，通常只有一条 |
| `user` | 用户说的话 | 每轮都要有 |
| `assistant` | 模型说过的话 | **多轮对话时，历史回答要按这个 role 塞回去** |

### 响应（模型返回的）

```json
{
  "choices": [
    {
      "message": {"role": "assistant", "content": "回答文本"},
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 59,
    "completion_tokens": 241,
    "total_tokens": 300
  }
}
```

**为什么是 `choices` 数组而不是直接 `message`？**
因为接口设计上支持 `n` 参数——一次生成多个候选回答。默认 `n=1`，所以取 `choices[0]`。

**`finish_reason` 的取值要认识**：

| 值 | 含义 |
|---|---|
| `stop` | 正常结束 |
| `length` | **被 max_tokens 截断了**（回答不完整，要警惕） |
| `tool_calls` | 模型要调工具 ← **这是 L4 的核心！** |

## 三、正课二：token —— 你必须建立的成本意识

### token 是什么

**token = 模型处理文本的最小单位**，不等于字、不等于词。

- 英文：约 1 token ≈ 4 个字符
- 中文：约 1 token ≈ 1~1.5 个汉字

### 实测数据（我刚跑你的项目拿到的真实数字）

```
提问："用一句话解释什么是 LCVR。"
prompt_tokens:     59     ← 你发过去的
completion_tokens: 241    ← 模型回答的
  └─ reasoning_tokens: 203   ← 其中 203 是「思考」消耗的！
total_tokens:      300
cost:             0.0013615
```

**⚠️ 发现了一个重要事实**：`Qwen3.8-27B` 是**推理模型**，自带思维链（Chain-of-Thought，CoT）。它回答 241 个 token 里，**203 个花在内部思考上**。

**这带来三个工程影响**：

| 影响 | 说明 |
|---|---|
| **贵** | 答案才 38 token，思考花了 203。你付了 5 倍的钱 |
| **结果不确定** | 同样的 temperature，思考过程不同，答案措辞会变 |
| **延迟高** | 思考要时间，响应变慢 |

**面试时这是加分点**：如果你能说出「我用的是推理模型，所以对延迟和成本做了额外考虑」，比只会说「我调了个 API」强得多。

### 成本意识（要养成）

```python
answer, usage = chat_once_with_usage("问题")
print(f"这次花了 {usage['total_tokens']} tokens，约 {usage['cost']:.6f} 元")
```

**为什么重要**：做 Agent 时，一次用户提问可能触发 5~10 次 API 调用（每步都要问模型）。**成本是乘积级放大的。**

## 四、正课三：temperature 与采样参数

### temperature（温度）

**控制随机性**。范围通常 0~2。

| 值 | 行为 | 适用 |
|---|---|---|
| `0` ~ `0.3` | 几乎确定，同样输入几乎同样输出 | **事实问答、代码、数据提取** ← 你的场景 |
| `0.7` | 平衡 | 通用对话 |
| `1.0`+ | 发散、有创造力 | 创意写作、头脑风暴 |

**实测对比**（我跑出来的真实结果）：

```
temperature = 0.1：
"斯托克斯参量是用于描述光波偏振态的四个实数参数，可完整表示光的总强度及线偏振、圆偏振等偏振信息。"

temperature = 1.0：
"斯托克斯参量是用四个实数（总强度及线、圆偏振分量）完整描述一束光偏振态的参数。"
```

**注意**：即使 `temperature=0.1`，**也不是完全确定**——因为底层是概率采样。这是「**把概率系统当确定性系统用**」这个坑的根源。

### 其他常用参数

| 参数 | 作用 | 建议 |
|---|---|---|
| `max_tokens` | 限制回答长度 | 设合理上限，防止跑飞烧钱 |
| `top_p` | 核采样，另一种控随机性 | **和 temperature 别同时调**，选一个 |
| `stream` | 流式输出 | L7 会用到（打字机效果） |
| `stop` | 遇到这些字符串就停 | 控制输出格式时有用 |

## 五、正课四：上下文窗口

**上下文窗口 = 模型一次能「看见」的最大 token 数**（输入 + 输出加起来）。

**为什么你必须懂**：

1. **超了会怎样**：直接报错，或静默截断（更可怕，你不知道信息丢了）
2. **这是 RAG 存在的根本原因**——文档太长塞不进去，所以要先检索、只塞相关的几段
3. **Agent 里更容易爆**——工具调用结果、历史对话、系统提示全占窗口

**工程习惯**：
```python
# 每次调用后检查用量，防止悄悄逼近上限
if usage["total_tokens"] > 0.8 * LIMIT:
    logger.warning("上下文已用 %.0f%%，考虑压缩历史", usage["total_tokens"] / LIMIT * 100)
```

⚠️ **限额的具体数字请你自己查**——不同模型的窗口大小不同，**不要凭印象填**。查到了告诉我。

## 六、正课五：Prompt 工程（够用原则）

**核心认知**（调研共识）：

> **Prompt 决定下限，架构决定上限。**

所以：**要认真学，但别学太久**。L2 里够用的部分如下。

### 1. 结构化提示词：四段式

```
【角色】你是光学领域的实验数据分析助手。
【任务】基于给定的实验数据回答问题。
【约束】
  - 只使用材料中出现的数字，不得推测
  - 材料中没有的信息，明确回复「材料中未包含」
  - 数字保留与原文一致的有效位数
【输出格式】先给结论，再列数据来源
```

**四段**：角色 / 任务 / 约束 / 输出格式。**这四样齐了，提示词基本不会太差。**

### 2. 你的项目里已有的例子（`rag_agent.py`）

```python
SYSTEM_PROMPT = """你是「光学实验数据问答助手」，专注偏振测量与光学实验领域。

工具使用规则：
1. 凡涉及偏振仪、LCVR、斯托克斯参量等专业问题，必须先调用工具检索知识库...
2. 打招呼、闲聊可直接回答，不必检索。
3. 严格基于检索内容作答，不得编造；知识库中没有的内容，明确回复「知识库中未找到相关答案」。
4. 回答要条理清晰、专业准确，必要时分点说明。"""
```

**逐条对照四段式**——它做对了什么、少了什么？

### 3. 防幻觉的两条实用技巧

| 技巧 | 写法 |
|---|---|
| **给退路** | 「材料中没有 → 明确说『材料中未包含』」← **不给退路，模型就会编** |
| **要求引用** | 「引用时标明来自哪份材料」← 逼模型核对，减少编造 |

### 4. 常见错误

| ❌ 错误 | ✅ 正确 |
|---|---|
| 「不要编造」 | 「**材料中未包含的内容，回复『材料中未包含』**」（正面指令比否定指令有效） |
| 一次塞 20 条规则 | 规则分优先级，核心 3~5 条 |
| 规则说「回答专业一点」 | 明确「保留 4 位有效数字」「用表格输出」 |
| 提示词硬编码在代码里 | **抽成独立文件**（L7 会讲，成熟项目都这么干） |
